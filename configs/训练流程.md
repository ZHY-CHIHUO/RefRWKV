## Stage 1：纯扩散基线（验证 IMA 修复）

**配置**：`configs/sd2_ref_gan_stage1_baseline.yaml`

**目标**：连续 4 小时无 CUDA 错误，loss 平滑衔接。

**启动**：

```bash
nohup python scripts/train_sd2_gan.py \
  --config configs/sd2_ref_gan_stage1_baseline.yaml \
  > logs/stage1.log 2>&1 &
```

**启动后 5 分钟内检查**：

```bash
# 确认开关全关
grep "v2 开关" logs/stage1.log

# 确认 resume 成功
grep "Restored all states" logs/stage1.log
```

**每小时检查**：

```bash
# loss 是否平滑
grep "train/G_diff_hr" logs/stage1.log | tail -5

# 有无 CUDA 错误（无输出 = 健康）
grep -i "illegal memory\|CUDA error" logs/stage1.log
```

**通过标准**（全部满足才可进入 Stage 2）：

1. 启动日志出现 `v2 开关: use_sr_condition=False, ... dtex_conf_weight=False`
2. `train/G_diff_hr` 从 resume 点平滑衔接，无尖峰
3. **连续 4 小时以上无任何 CUDA 错误**
4. 显存稳定（无 OOM 或持续增长）

**注意**：由于 `use_semantic: false`，Stage 1 没有语义路径。达标即可手动中断（Ctrl+C 或 `kill` nohup 进程），不需要跑满 epoch。

## Stage 2：语义金字塔重训 + SR 条件

**配置**：`configs/sd2_ref_gan_stage2_semantic.yaml`

**目标**：语义路径在新 WKV 公式下重训收敛，验证 SR 条件的增益。

**启动**：

```bash
nohup python scripts/train_sd2_gan.py \
  --config configs/sd2_ref_gan_stage2_semantic.yaml \
  > logs/stage2.log 2>&1 &
```

**启动后 5 分钟内检查**：

```bash
# 确认 v2 开关
grep "v2 开关" logs/stage2.log

# 确认 pyramid 权重被跳过
grep "跳过.*semantic_pyramid" logs/stage2.log

# 确认预期内新增参数
grep "预期内新增参数" logs/stage2.log
```

**关键观察点（前 1500 步）**：

```bash
# loss 尖峰与回落过程
grep "train/G_diff_hr" logs/stage2.log | head -20
```

预期曲线：resume 瞬间跳高（金字塔随机初始化）→ 几百步内快速下降 → 1500 步内回到 0.05~0.12 区间。

**如果 3000 步后仍高于 0.15**，停下来检查——可能 `sr_conditioner` 的位置编码或拼接有误。临时改 `use_sr_condition: false` 跑 500 步对比，若回落正常，问题在 SR 条件分支。

**每 epoch 检查**：

```bash
# val/psnr 趋势（应逐渐追平 Stage 1 的 ~22.05）
grep "val/psnr" logs/stage2.log | tail -5
```

**通过标准**：

1. `train/G_diff_hr` 尖峰回落至 0.05~0.12 区间
2. val/psnr 追平或超过 Stage 1 最佳值（~22.05）
3. 全程无 CUDA 错误
4. 跑 2~3 个完整 epoch 确认稳定

**时长**：约 1~1.5 天。

## Stage 3：纹理迁移完整链路

**配置**：`configs/sd2_ref_gan_stage3_texture.yaml`

**开启的模块**：`use_self_sim_transfer` + `use_confidence_gate` + `use_temporal_gate` + `lambda_diff_sr` + `lambda_lpips`

**目标**：LPIPS 下降，重复纹理区一致性改善。

**启动**：

```bash
nohup python scripts/train_sd2_gan.py \
  --config configs/sd2_ref_gan_stage3_texture.yaml \
  > logs/stage3.log 2>&1 &
```

**启动后 5 分钟内检查**：

```bash
# 确认 v2 开关正确
grep "v2 开关" logs/stage3.log

# 确认 missing keys 只有 sim_transfer 相关
grep -A 10 "missing keys\|预期内新增" logs/stage3.log | head -15
```

**训练中关注三个信号**：

```bash
# 1. 前 200 步的扰动与回落（sim_transfer 随机初始化的正常代价）
grep "train/G_diff_hr" logs/stage3.log | head -30

# 2. LPIPS 趋势（核心指标，应该下降）
grep "train/G_lpips" logs/stage3.log | tail -10

# 3. 每个 epoch 的 val/lpips
grep "val/lpips" logs/stage3.log
```

**可视化检查（每 2 个 epoch）**：

打开 TensorBoard 中 `validation_tmp` 的拼图，重点看两类区域：

- **重复纹理区**（农田、建筑群、停车场）：纹理是否比 Stage 2 更连贯、更一致
- **变化区域**（如果有新建/拆除）：是否出现"贴上去的错误纹理"

**通过标准**：

1. `train/G_diff_hr` 前 200 步轻微扰动后回落
2. val/lpips 相对 Stage 2 可见下降
3. 可视化中重复纹理区一致性改善，且无"贴错纹理"的情况
4. 全程无 CUDA 错误

**时长**：约 1 天。

## Stage 4：GAN 精调 + D_tex 置信加权

**配置**：`configs/sd2_ref_gan_stage4_gan.yaml`

**开启的模块**：GAN + swap test + `dtex_conf_weight`

**目标**：感知质量精调，LPIPS 进一步下降。

**启动**：

```bash
nohup python scripts/train_sd2_gan.py \
  --config configs/sd2_ref_gan_stage4_gan.yaml \
  > logs/stage4.log 2>&1 &
```

**启动后 5 分钟内检查**：

```bash
# 确认 v2 开关
grep "v2 开关" logs/stage4.log

# 确认判别器加载
grep "Discriminator 权重不在" logs/stage4.log
```

**新增监控项**：

```bash
# D_tex 置信占比：健康区间 0.4~0.6
grep "train/D_tex_conf" logs/stage4.log | tail -10

# GAN loss 趋势
grep "train/G_gan\|train/D_sem\|train/D_tex" logs/stage4.log | tail -10
```

**三个警示区间**：

| `D_tex_conf` 均值 | 含义 | 处理 |
|---|---|---|
| 长期 < 0.2 | 大部分样本 LCA 匹配失败 | 先查数据对齐或 ref 增强强度；用 `ref_aug_probs` 全 0 跑 100 步看是否回升 |
| 长期 > 0.8 | 置信图无区分度 | 检查是否误用了 scale1 的 cos_map（`raw_cos_maps[1]` 应为 scale2） |
| 剧烈波动 | swap test 与加权在打架 | 把 `swap_ratio` 降到 0.3 试试 |

**通过标准**：

1. `train/D_tex_conf` 稳定在 0.4~0.6 区间
2. val/lpips 相对 Stage 3 进一步下降
3. G/D loss 无持续发散（D_tex 的 hinge loss 在 0~2 区间波动为正常）
4. 全程无 CUDA 错误

**时长**：约 1~2 天。

## 故障速查表

| 症状 | 最可能原因 | 处理 |
|---|---|---|
| Stage 1 又出现 CUDA IMA | 后端重写未生效或问题不在语义模块 | 检查 `globalsemanticmodule.py` 是否真是纯 PyTorch 版；若确认，IMA 来源在 adapter 的 `RUN_CUDA` |
| Stage 2 loss 尖峰后 3000 步不回落 | `sr_conditioner` 输出尺度异常 | 临时改 `use_sr_condition: false` 跑 500 步对比 |
| Stage 3 resume 后 missing keys 超出 sim_transfer | 配置传递链断裂 | 检查 `rwkv_cfg` 在 yaml 里的缩进层级 |
| Stage 3 LPIPS 上升而非下降 | 传播过强，纹理被"抹匀" | `self_sim_init_alpha` 降到 0.15 重启 Stage 3 |
| Stage 4 `D_tex_conf` 长期 < 0.2 | 数据对齐或 ref 增强过强 | 先用 `ref_aug_probs` 全 0 跑 100 步看 conf 是否回升 |
| 任何阶段 OOM | sim_transfer 亲和矩阵显存（~156MB） | 确认没有误开 scale1 传播；`expandable_segments` 保持注释状态 |
