# RefRWKV 四阶段训练流程

> 配置重构说明：各阶段 YAML 现为 configs/base.yaml 的薄覆盖（base: 引用，只写差异），训练命令不变；另支持 --overrides key=value 覆盖任意字段（点分路径），便于消融实验。启动时会打印模块激活摘要，Stage 3 已恢复完整纹理链路（self-sim / 门控 / LPIPS 开启）。

### SR 权重加载逻辑（先理解再跑）

| 场景 | SR 权重来源 |
|---|---|
| `sr_fixed=True`（四阶段常态） | ① `sr.ckpt_path` 存在 → 独立 SR checkpoint；② 否则 `resume_ckpt` 中提取 `sr_model.*`；③ 都没有 → 报错 |
| `sr_fixed=False`（微调） | 只能从 `resume_ckpt` 加载（SR 状态随训练更新，必须恢复最新） |

确认两个关键文件存在：

```bash
ls checkpoints/refrwkv_sr/best.ckpt          # Stage 1 首次训练的 SR 来源
ls checkpoints/sd2_ref_gan_Stage1/last.ckpt  # Stage 2 的 resume 来源（Stage 1 跑完后才有）
```

### 后台管理命令速查

**集群：**

```bash
# 查看日志（实时）
tail -f ~/logs/slurm/stageN-*.out

# 查看作业状态

# 停止作业

```

**单机：**

```bash
# 查看日志（实时，N 换成 1/2/3/4）
tail -f logs/stageN.log

```

**中断恢复（两种方式通用）：** 训练中断后重交同一条命令即可——脚本会自动检测实验目录下的 `last.ckpt` 断点续训，不需要手动指定 `--resume`。

## 7. 故障速查表

| 症状 | 最可能原因 | 处理 |
|---|---|---|
| 启动报 `ValueError: SR 权重无处加载` | `sr.ckpt_path` 不存在且无 `resume_ckpt` | 检查 `sr.ckpt_path` 路径或指定 `--resume` |
| Stage 2 loss 尖峰 3000 步不回落 | `sr_conditioner` 输出尺度异常 | 临时 `use_sr_condition: false` 跑 500 步对比 |
| Stage 3 missing keys 超出 sim_transfer | 配置传递链断裂 | 检查 `rwkv_cfg` 在 yaml 里的缩进层级 |
| Stage 3 LPIPS 上升 | 传播过强，纹理被"抹匀" | `self_sim_init_alpha` 降到 0.15 重启 Stage 3 |
| Stage 4 `D_tex_conf` 长期 < 0.2 | 数据对齐或 ref 增强过强 | `ref_aug_probs` 全 0 跑 100 步看是否回升 |
| 任何阶段 OOM | sim_transfer 亲和矩阵显存 | 确认没有误开 scale1 传播；`expandable_segments` 保持注释 |
| 训练中断后恢复 | — | 重交同一命令即可，`last.ckpt` 会被自动检测断点续训 |
